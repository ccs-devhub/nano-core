** nano.config.json - THE BIND LAW (AI-RUNNABLE)
   The file has no =web= block today. Add:
   #+begin_src js
   "web": {
     "enabled": true,
     "bind": "0.0.0.0",
     "port": 4777,
     "public_url": "https://bot.kyonax.tech",
     "session_ttl_h": 2,
     "trust_proxy_header": false,
     "access_team_domain": "<team>.cloudflareaccess.com",
     "access_aud": "<64-char hex AUD tag>"
   }
   #+end_src

   =bind: 0.0.0.0= is non-negotiable - a docker publish forwards to
   the container's EXTERNAL interface and can never reach a server
   bound to the container's own loopback. Without it the published
   port reaches nothing and THE FAILURE PRESENTS AS A CLOUDFLARE 502.

   =public_url= is load-bearing twice: it makes the OAuth
   =redirect_uri= public instead of loopback, and =isSecure()= is
   literally =public_url.startsWith('https://')= - a PREFIX TEST ON
   THE CONFIG STRING, and the only thing emitting the Secure cookie
   flag.

   ALWAYS validate before any restart - =loadConfig= THROWS on an
   invalid file, so a typo is a bot outage:
   #+begin_src bash
   ssh nano-vps 'python3 -m json.tool /srv/bots/the-creator/state/nano.config.json > /dev/null && echo JSON-OK'
   #+end_src

* Phase 3 - Cloudflare (ALL OWNER-KEYSTROKE)
  No Cloudflare API token exists in =pass=; every step is dashboard
  work. Dependency order, all four hazards as one sequence:

  1. DISCORD PORTAL FIRST. Register
     =https://bot.kyonax.tech/auth/callback= exactly, no trailing
     slash. Discord rejects unregistered redirect URIs, so setting
     =public_url= first kills login outright.
  2. TUNNEL TOKEN. Replace the placeholder in
     =/etc/cloudflared/tunnel.env= (currently 26 chars; a real token
     is ~180+), keep 0600 cloudflared:cloudflared, then
     =systemctl enable --now cloudflared=. Expect four
     =Registered tunnel connection= lines.
  3. ACCESS APPLICATION - BEFORE THE ROUTE. Self-hosted,
     =bot.kyonax.tech=, Allow / owner email / One-time PIN. ENABLE
     MANAGED OAUTH so Access returns 401 not a 302 (without it an
     expired session turns every XHR into an opaque HTML redirect the
     SPA cannot interpret). RECORD THE AUD TAG - it is the audience
     claim F13 pins, and without it the JWT check either fails closed
     or accepts a token minted for ANY application in ANY account.
  4. TUNNEL ROUTE. Public Hostname =bot= . =kyonax.tech= -> HTTP ->
     =127.0.0.1:4777=. THIS AUTO-CREATES THE CNAME - do not hand-create
     DNS, and ignore the Hostinger panel entirely (its records for
     this zone are INERT; the domain is delegated to Cloudflare).
     =127.0.0.1:4777= is correct here and does not contradict the bind
     law: cloudflared runs on the HOST, where the published socket
     genuinely is loopback.
  5. /health APPLICATION - a SEPARATE path-scoped app with a SERVICE
     AUTH policy and token. NOT a Bypass: Bypass disables all Access
     controls AND logging. Order it above the parent app. Blocked on
     F6, which is blocked on F13.
  6. RATE-LIMIT RULE. Round 2 reallocated the single free rule to
     PLAN B - with Access fronting the hostname, anonymous traffic
     never reaches =/auth/login=, so the rule would guard an
     already-unreachable surface.

* The monitoring patch
  =fleet-alert.sh= reads container status, restart count, backup age,
  a log-scraped guild count, host disk and host memory. IT NEVER OPENS
  =heartbeat.json=, so =loop_p99_ms=, =rest_429s=, =db.wal_mb=,
  =db.sqlite_mb=, =heap_used_mb=/=heap_limit_mb= and
  =gateway.invalidated_count= are all emitted every 300 s and all
  discarded.

  =jq= IS NOT INSTALLED on this VPS. =python3= 3.13.5 is. Write the
  patch in python3; installing jq is an unnecessary state change.

  The two rules that matter:
  - EVENT-LOOP P99 is the extraction trigger - alert on sustained
    >100 ms across TWO consecutive sweeps (the alerter runs every 5
    min and the heartbeat is 300 s, so one sweep is one sample).
    Never on a single spike.
  - =rest_429s= IS A TREND, NOT A THRESHOLD. It includes pre-emptive
    bucket waits, so non-zero is normal and healthy. Alert on >=25 new
    events per 5-minute window, twice consecutively. A counter that
    went DOWN means the process restarted - treat the previous value
    as 0.

  Add a tunnel-liveness check gated on the unit being enabled, so it
  stays silent until the owner completes the wiring.
